## Структура
- `site/` — готовый сайт, выкладывается как есть (сборки нет). `site/.htaccess` — для Apache/cPanel (Hostko); `site/_headers` — только для Netlify/Cloudflare, в архив для хостинга не входит. `site/assets/js/film.js` — движок сцены; `page.js`, `form.js`; `site/config.js` — ключ Web3Forms, e-mail, WhatsApp. Тексты скриптов — в блоке `window.MTL = {…}` в начале каждого `index.html`.
- `previews/` — одностраничные файлы SI/EN для просмотра без хостинга (всё внутри файла). Это снимки: при правке `site/` их нужно собирать заново (скрипта сборки нет, см. «Известные ограничения»).
- `artifacts/age-of-sail-live.html` — копия опубликованной страницы.
- `docs/` — инструкция для веб-мастера (`01_INSTRUCTION_RU.docx`), вычитка словенского (`02_…docx`), журнал решений (`MAXTRADE_export_memory.md`), записка 25.10, макет вариантов кустов (`mockups/`).
- `inputs/` — исходные английские карточки с текстами (`texts/`), скрипты логистической карты (`map/`), логотип (`brand/`).
- `tools/` — `patch_film.py`, `port_oct25.py` (скрипты правок движка, одноразовые), `snap.js` (кадр сцены по `#film=N`), `errs.js` (ошибки загрузки), `experiments/bush-variants-ABC.js` (варианты кустов A/B/C).
- `scripts/` — `make-hosting-zip.sh` (архив для загрузки в `public_html`, кладёт в `releases/`), `make-package.sh` (zip с инструкциями для веб-мастера), `serve.sh` (локальный просмотр).
- `releases/` — архивы, которые выкладывались на хостинг (не перезаписывать, новое имя с датой).
- `docs/HOSTING_AND_LAUNCH.md` — состояние хостинга, DNS (значения до/после, откат), SSL, формы, открытые пункты.
- `docs/WEBSITE_METHODOLOGY.md` — общая методичка для новых сайтов. `docs/launch-checklist.html` — чек-лист запуска.

## Как выкладывать правки
- Править в `site/`, собрать `scripts/make-hosting-zip.sh`, загрузить в cPanel → File Manager → `public_html` → Extract с заменой. Подробно в `docs/HOSTING_AND_LAUNCH.md`.
- Если правка сделана прямо на сервере (File Manager → Edit), сразу повторить её в репозитории и записать в `docs/HOSTING_AND_LAUNCH.md`.
- В `public_html` не удалять служебные файлы хостинга: `.well-known`, `.403h.shtml`, `.404h.shtml`, `.user.ini`, `php.ini`.

## Как работать с 3D
- Кадр сцены для проверки: открыть страницу с `#film=N` (N от 0 до 10; 0–1 плантация, ~3 порт, ~5.6 Копер, ~7 склад, ~9 карта). Для автоматического снимка см. `tools/snap.js` (в `film.js` нужно временно добавить остановку цикла кадров, как в начале `snap.js`/истории).
- Флаг `LOWP` = телефон (ширина < 760 или сенсорный экран < 820). На телефоне картинка рисуется в плотности до ×2,5, при тормозах опускается не ниже ×1,5. Если реальные телефоны тормозят — сначала снижать `PR0` в `film.js` (строка с `var PR0`).
- Скриншоты в песочнице идут через программный рендер (swiftshader): долго и без реальной оценки FPS. Не делать выводов о плавности по ним.
- Правки сцены вносить в `site/assets/js/film.js`, затем перенести то же в `previews/` и `artifacts/` (одинаковый кусок кода), иначе версии разойдутся.
